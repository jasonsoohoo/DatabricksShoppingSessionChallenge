# Pipeline

1. The Rust identity reader interns names from the link files in a single byte buffer and resolves their integer indices with union-find. Event routing and click preparation share the immutable index, which stores the canonical root and its hash for routing. Path compression and byte-wise minimum roots preserve names contributed by link-only IDs. Unlinked IDs fall back to their original bytes.
2. A std-only Rust reader scans LF-delimited byte records on up to NCPU workers, with line-aligned event input chunks. It checks the entire field layout before removing wrapping quotes and preserves CR in values. Timestamps use checked ASCII arithmetic and explicit Gregorian and offset limits.
3. Event workers hash IDs into 256 in-memory partitions. Each retains exact ID bytes and normalized ingestion time, including invalid copies. Open-addressed tables compare keys byte for byte and select the earliest copy before removing invalid winners. The winning rows retain the user, product, event time and price needed by the session labeler. Memory for this stage scales with input size.
4. Rust routes winners by canonical person, groups them by exact ID and sorts events within each group by time. A gap strictly over 30 minutes starts a new session. Equal times share a label. DuckDB reads the labels and purchase fields from Arrow buffers, aggregates by session and joins products for daily purchase-category totals. Unknown purchased products use the unknown category. All aggregates use the UTC session start date, including purchases after midnight.
5. The native click reader validates IDs and timestamps, resolves each user through the identity map, and looks up the campaign code before emitting a typed Arrow batch. Unknown campaigns are discarded. Identical copies have the same winner and assist semantics. DuckDB exports a timeline ordered by person, timestamp, and descending click ID, with the session after clicks at the same time. Rust workers read contiguous ranges of this file. Every range starts at a person boundary so each worker sees complete click histories. After the sweeps, the process sums worker results by campaign and day. Each sweep expires clicks older than seven days, credits the last eligible click, and counts one assist per active campaign. Per-campaign reference counts preserve exact semantics for repeat clicks. Campaign/day totals include assist-only rows and organic sessions.
6. The runtime writes one typed Parquet file per table. A per-run scratch directory holds intermediates and DuckDB spills. The host runner caps CPU and RAM, disables swap and network, and uses an unprivileged UID.

The exact local baseline remains recoverable in Git. Implementation-specific performance and known scale failures are recorded in BENCHMARKS.md.
