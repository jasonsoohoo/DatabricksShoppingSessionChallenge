# Pipeline

1. The Rust identity reader interns names from the link files in a single byte buffer and resolves their integer indices with union-find. Event routing and click preparation share the immutable index, which stores the canonical root and its hash for routing. Path compression and byte-wise minimum roots preserve names contributed by link-only IDs. Unlinked IDs fall back to their original bytes.
2. A std-only Rust reader scans LF-delimited byte records on up to NCPU workers, with line-aligned event input chunks. The event reader indexes delimiters and quote counts in blocks of complete records from its input buffer. Workers take the largest remaining ranges first. It checks the entire field layout before removing wrapping quotes and preserves CR in values. Timestamps use checked ASCII arithmetic and explicit Gregorian and offset limits.
3. Event workers hash IDs into 256 in-memory partitions. Each retains exact ID bytes and normalized ingestion time, including invalid copies. Open-addressed tables compare keys byte for byte and select the earliest copy before removing invalid winners. The winning rows retain the user, product, event time and price needed by the session labeler. Memory for this stage scales with input size.
4. Rust routes winners by canonical person, groups them by exact ID and sorts events within each group by time. A gap strictly over 30 minutes starts a new session. Equal times share a label. Rust counts events and sums 64-bit revenue while labeling each session. It exports each positive purchase and emits one placeholder for a session without purchases. Exactly one row per session carries its event count and revenue. DuckDB reads that row for session totals and joins the purchase rows to products for daily category totals. Unknown purchased products use the unknown category. All aggregates use the UTC session start date, including purchases after midnight.
5. Rust validates clicks and resolves each user and campaign. Attribution routes valid clicks to the same hash partitions as the canonical-person session labels. Within each partition, workers group by exact person and sort clicks by timestamp and descending bytewise click ID. They scan contiguous session labels for each person, add clicks through each session start, expire clicks older than seven days, and count one assist per active campaign. The final eligible click receives credit, with organic credit for an empty window. A reduction sums worker totals by campaign and day, including assist-only rows.
6. The runtime writes one typed Parquet file per table. A per-run scratch directory holds intermediates and DuckDB spills. The host runner caps CPU and RAM, disables swap and network, and uses an unprivileged UID.

The exact local baseline remains recoverable in Git. Implementation-specific performance and known scale failures are recorded in BENCHMARKS.md.
